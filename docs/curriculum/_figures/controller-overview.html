Who fires the edges

Nine modes. Ready leads to Proposing, where the policy proposes a trial or asks to stop. A proposed trial goes to Authorizing, where the gate allows it into the Trial in flight group (Dispatching, Running, Scoring) or rejects it back to Ready. Every closed trial, rejection, invalid reply, and stop request returns to Ready along the right side. A timeout or restart in flight leads to Reconciling, which resumes the trial or resolves it back to Ready. From Ready, or on a cancel or deadline anywhere in Search, the run moves to Stopped, and the holdout score moves it to Done.

Mode

Ready

Between policy turns. The controller checks its limits here before every turn. If no stop is requested and every limit has room, it builds the policy's context and moves to Proposing. Otherwise it moves to Stopped. Every return path ends in Ready. The small loop logs and ignores a late reply for a trial that is already closed.

Event source

Policy

Proposes a trial or asks to stop, only in Proposing and only for the current turn. Those are its two choices. Its decoder reports a reply it cannot use as invalid output, the third exit from Proposing, which returns to Ready.

Can the runtime refuse it? Yes. The gate or a guard can reject the request.

Edges it fires are highlighted.

Event source

Gate

Allows or rejects the proposed trial. An approval binds the exact arguments it checked.

Can the runtime refuse it? Not applicable. The gate is runtime code.

Edges it fires are highlighted.

Event source

Scheduler

Accepts, finishes, or fails a job, and answers lookups by operation ID or job ID.

Can the runtime refuse it? No. The job runs whether or not the controller still wants it.

Edges it fires are highlighted.

Event source

Evaluator

Returns a score, or a stored score on lookup. It also scores the holdout once at the end. Only a score can promote a candidate.

Can the runtime refuse it? No. A score can arrive late or twice.

Edges it fires are highlighted.

Event source

Clock, operator, host

Timeouts, the deadline, a cancellation, and the recovered event after a restart.

Can the runtime refuse it? No. The runtime must absorb these events.

Edges it fires are highlighted.

Event source

Controller

Checks the limits in Ready, then starts a policy turn or stops the search.

Can the runtime refuse it? It is the runtime's own rule.

Edges it fires are highlighted.

Mode · the policy's turn

Proposing

The policy proposes a trial with its arguments, or asks to stop. A reply the decoder cannot use, or one that misses its deadline, counts as invalid output. These are the only edges the policy chooses.

Mode

Authorizing

The gate checks the proposed trial against the protocol. If it allows the trial, the controller records it and reserves compute before anything is sent. If it rejects the trial, the reason goes back to Ready.

Reconciling

A reply went missing, or the process restarted. The controller looks up stored results by their IDs before it decides anything, and it starts no new trial.

Mode

Stopped

The search is over and the incumbent is frozen. A trial can still be pending, and late evidence closes it along the small loop. No edge leads back to a new trial.

Mode

Done

The holdout score is recorded, once. No transition leaves Done.

Group

Search

Every mode from Ready to Reconciling. A cancellation or the deadline moves the run to Stopped from any of them, and the policy cannot prevent it.

Group

Trial in flight

Dispatching, Running, and Scoring: the modes that wait on the scheduler or the evaluator. A timeout or a restart in any of them moves the run to Reconciling.
