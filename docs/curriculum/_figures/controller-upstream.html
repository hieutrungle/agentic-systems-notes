  1. The loop as written

    Upstream Edit, run, read the score, log, keep or reset, and repeat until a person interrupts. Enforced by: The agent, following program.md. State: Git, run.log, results.tsv, and the agent's context.

    Redesign The gate, the process host, the pinned evaluator, and the controller. Rows 1–23.

    At commit 228791f, the policy carries out every rule, including the rules that judge its own work. The steps follow one experiment and move each rule that must hold whatever the policy proposes.

  2. Propose a patch

    Upstream Edit train.py with an experimental idea. Enforced by: The agent. State: Git branch.

    Redesign The policy chooses, and the gate checks. Row 3.

    Update, row 3

    Count the proposal. Record the diff, its hash, and whether it is a new idea or a fix of an earlier idea.

    This choice stays with the policy. Judgment pays here, and the gate can check that the patch is legal before anything runs.

  3. Check the diff

    Upstream Edit only train.py, and add no packages. Enforced by: The agent. State: The diff.

    Redesign The gate. Rows 6 and 7.

    Guard, row 7

    The approval binds the recorded diff hash, prepare.py and the lock file match their pinned hashes, and no stop is requested

    The rule becomes a guard on the diff, and the approval binds the diff's hash. Row 6 rejects a patch that touches another file before anything is committed.

  4. Commit the candidate

    Upstream Commit the edit with git commit. Enforced by: The agent. State: Git branch.

    Redesign The controller. Row 7.

    Update, row 7

    Mint trial and run IDs. Create the candidate commit on its own ref, and record it with the base commit. Count the trial and reserve one 7-minute run slot. Commit the checkpoint, then ask the process host to launch.

    The branch does not move here. Only a promotion in row 11 moves it. As in Figure 2, step 7, the checkpoint is committed before anything is sent.

  5. Run under a time cap

    Upstream Stop training after 5 minutes, and kill a run after 10. Enforced by: A break in train.py, and the agent. State: Code the agent edits, and the agent's shell session.

    Redesign The process host, which kills the run at 7 minutes. Row 10.

    Update, row 10

    Covers a nonzero exit, missing weights, or a kill at the 7-minute cap. Store the diff and log tail for a possible fix, charge the slot, and close the trial as a crash.

    5 and 10 minutes are upstream parameters. The 7-minute cap is schematic: the budget plus an allowance for startup and saving. A run that deletes the break can still train for up to that allowance.

  6. Choose a fix, within a limit

    Upstream Read the stack trace, try a fix, and give up after a few attempts. Enforced by: The agent's judgment. State: The agent's context.

    Redesign The policy picks the fix, and the gate counts attempts. Rows 3 and 6.

    Rejection reasons, row 6

    The diff touches another file, adds a dependency, or does not apply to the incumbent commit, or it fixes an idea that has used three attempts

    A fix is a complete diff against the incumbent, labeled with the idea it fixes. A policy could mislabel a fix as a new idea, so the trial cap is the bound that actually holds.

  7. Measure with a pinned evaluator

    Upstream Read val_bpb from run.log, and treat an empty result as a crash. Enforced by: The agent, reading text that train.py prints. State: run.log.

    Redesign A pinned evaluator that scores the saved weights. Rows 9 and 11.

    Guard, row 9

    The run ID matches the pending trial, the exit status is 0, and the weights were saved

    Upstream, the loss comes from the model code in train.py. The pinned evaluator computes bits per byte from the candidate's logits after a causality check, and training runs without the validation or holdout shard mounted.

  8. Keep or reset by rule

    Upstream Keep the commit if val_bpb is lower, otherwise reset. Enforced by: The agent. State: Branch head.

    Redesign The controller, on the pinned evaluator's score. Row 11.

    Update, row 11

    Charge the slot. If val_bpb is strictly lower than the incumbent's, record the candidate commit as the incumbent. Close the trial. After the checkpoint, set the branch to the incumbent commit.

    Keep or reset is a row fired by the pinned evaluator, not a decision the agent writes.

  9. Record from the ledger

    Upstream Append a row to results.tsv. Enforced by: The agent. State: A file outside git.

    Redesign The controller's ledger. Rows 10 and 11 close trials.

    Report

    results.tsv is regenerated from the ledger, one row per closed trial

    A restart cannot append a second row for the same trial, because the report is rebuilt from closed trials.

  10. Stop by rule

    Upstream Never stop, and never ask whether to continue. Enforced by: A person who interrupts. State: Nowhere.

    Redesign The stop rule, the clock, and the operator. Rows 2, 4, and 12.

    Guard, row 2

    Row 12 stops the search on a cancel or the 8-hour deadline; the limits are schematic. The policy gains a request it did not have: it can ask to stop (row 4). A cancel leaves a record and a frozen incumbent, where killing the agent mid-command could leave a commit neither kept nor reset.
